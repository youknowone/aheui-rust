# 컴파흴러

**엔터프라이즈급 고성능 아희, 컴파흴러로 돌아왔다**

2015년, [알파희](https://github.com/aheui/rpaheui/)는 아희 성능의 대혁신을 일구어 냈습니다. 알파희 이전에는 누구도 아희가 이렇게 빨라질 줄은 몰랐죠.

알파희가 트레희싱짓으로 초고성능 엔터프라이즈 아희의 가능성을 보여준 지 11년. 컴파흴러는 비로소 그 다음 단계를 제안합니다.

컴파흴러는 아희 소스 코드를 **네이티브 바희너리로 컴파흴**합니다.

## 추천사

> 프로그래밍 언어 '아희'가 2005년에 탄생한 지 어느덧 만 20돌이 지났습니다. 아희는 복합적인 디자인 철학을 가지고 있는 언어이며, 그동안 Go(2009)나 Kotlin(2011), Rust(2012)와 같은 후속 언어들에 영향을 줬다고 자부하고 있습니다.
>
> 빠른 AI의 발달과 예측할 수 없는 국제 정세에 휩쓸려 컴퓨터 하드웨어는 점점 비싸지고 있습니다. 이를 상쇄시키기 위해 소프트웨어는 더 빠르고 단순해져야 하는 것이 순리겠지만, 소프트웨어조차 오히려 복잡하고 느려지고 있는 것이 현실입니다.
>
> 이번에 개발된 '컴파흴러'야말로 이 문제를 정면으로 돌파하는 기술입니다. 컴파흴러는 아희 코드를 실행하는 데에 걸리는 시간을 기존에 비해 수십 배 이상 빠르게 개선하여, 전세계의 컴퓨터 사용자들이 겪고 있는 하드웨어 성능 문제의 해결에 기여하고 있습니다. 이는 '작성한 코드의 유용성'이라는 아희의 핵심적인 철학을 잘 구현한 것이라 할 수 있겠습니다.
>
> 아희 기술의 발전이 다시 한 번 지구와 환경에 기여하는 것을 확인하게 되어 기쁩니다.
>
> — *Puzzlet Chung*

## 특징

- **컴파흴**: 아희 코드를 Rust 소스로 변환한 뒤 네희티브 바희너리를 생성합니다.
- **큰 정수 지원**: 기본으로 켜져 있습니다. 자근아희 위에 큰아희를 올린 <br/>아희<br/>아희<br/>키<br/>텍<br/>처<br/>로, 큰 정수가 실제로 필요해지기 전까지는 순수 `i64`와 동일한 속도로 동작합니다. 끈다고 더 빨라지지는 않습니다. 이미 빠르거든요.
- **다중 백엔드**: Rust 컴파흴러가 없으신가요? C 컴파흴러도 사용할 수 있습니다. 아니, 그것도 없으세요? 그럼 Cranelift 백엔드도 있습니다. 느리지만요.

## 성능

**[아희아희](https://github.com/aheui/aheui.aheui)**로도 더 이상 현대인의 느긋한 삶을 즐길 수 없습니다. 컴파흴러로 업그레이드하고 쉴새 없이 노동하세요!

```sh
time ./aheui.aheui < snippets/quine/quine.puzzlet.40col.aheui > /dev/null 
0.139 real  0.131 user  0.001 sys
time ./aheui.aheui < snippets/99bottles/99bottles.aheui > /dev/null
0.110 real  0.101 user  0.001 sys
```

## 설치

```sh
cargo install compaheuiler
```

`cargo`가 없다면 [rustup](https://rustup.rs/)을 먼저 설치하세요.

## 빌드

직접 빌드하고 싶다면:

```sh
cargo build --release
```

큰 정수가 기본으로 켜져 있습니다 (`malachite-bigint`). 다른 큰 정수 구현체를 쓰고 싶다면:

```sh
cargo build --release --no-default-features --features num-bigint
```

큰 정수 없이 순수 `i64`만으로 빌드하고 싶다면:

```sh
cargo build --release --no-default-features
```

Cranelift AOT 백엔드를 포함하려면:

```sh
cargo build --release --features cranelift
```

## 사용법

### 네희티브 바희너리 컴파흴

```sh
# 아희 소스를 컴파흴하여 실행 파일 생성
compaheuiler hello.aheui

./hello
```

컴파흴러는 아희 소스를 Rust 코드로 변환하고, `rustc`를 호출해 최적화된 네희티브 바희너리를 만듭니다.

자세한 사용법은 `compaheuiler --help`를 참고하세요.

### 라희브러리로 사용

```rust
let source = std::fs::read_to_string("program.aheui").unwrap();

// Rust 코드로 컴파일
let rs_code = compaheuiler::compile_to_rs(&source);

// C 코드로 컴파일
let c_code = compaheuiler::compile_to_c(&source);

// BigInt 지원 Rust 코드로 컴파일
let rs_bigint = compaheuiler::compile_to_rs_bigint(&source);
```

## 구조

```
아희 소스
  ↓
앟셈블러: 파싱 → CFG 생성 → 최적화
  ↓
┌─────────────┬──────────────┬────────────────┐
│  rgen.rs    │  cgen.rs     │  cranelift_    │
│  Rust 코드  │  C99 코드     │  backend.rs   │
│  생성       │  생성         │  AOT 기계어    │
└──────┬──────┴──────┬───────┴───────┬────────┘
       ↓             ↓               ↓
     rustc          cc           직접 실행
       ↓             ↓
   네희티브 바희너리
```

컴파흴러의 핵심은 앟셈블러(`ahsembler`) 크레이트에 있습니다. 아희 소스를 파싱하여 제어 흐름 그래프(CFG)를 구성하고, 온갖 최적화 패스를 거친 뒤 각 백엔드가 코드를 생성합니다. 자세한 내용은 앟셈블러의 문서를 참고하세요.

### 아희<br/>아희<br/>키<br/>텍<br/>처

**아희**<br/>
**아희**

**아희아희**와는 다릅니다!

**아희**<br/>
**아희**입니다!

큰 정수를 켜면 느려지는 거 아니냐고요? 아닙니다. 컴파흴러는 하나의 바희너리 안에 2개의 바희너리를 적층합니다. 저희는 그걸 자근아희와 큰아희라고 부릅니다.

**큰아희**<br/>
**자근아희**

처음에는 모든 값이 순수한 `i64`입니다. 산술 연산은 네이티브 `checked_add`, `checked_mul` 등을 사용하며, 큰 정수의 존재조차 모릅니다. 이 상태에서는 큰 정수를 끈 것과 성능 차이가 없습니다. 레지스터 하나에 플래그 하나, 분기 예측이 맞는 한 비용은 사실상 0입니다.

오버플로가 발생하는 순간, 모든 스택의 값이 꼬리표 표현으로 권한 상승됩니다. 홀수는 작은 정수(`v >> 1`), 짝수는 힙에 할당된 큰 정수 포인터. 자근아희에서 큰아희로 승격하는 셈입니다. 이후부터는 꼬리표 경로로 동작하되, 작은 정수끼리의 연산은 여전히 비트 시프트와 네이티브 산술만으로 처리됩니다.

정리하면 이렇습니다:

- **오버플로 전** (자근아희): 순수 `i64`. 큰 정수를 끈 것과 동일한 속도.
- **오버플로 후** (큰아희): 꼬리표 모드. 작은 정수는 여전히 빠르고, 진짜 큰 수만 큰 정수 경로를 탑니다. 살짝 느릴 수 있지만, 안되는거 보다 낫잖아요? 안타깝게도 큰 정수를 쓰는 충분히 느린 아희코드가 없어서 벤치마크는 없습니다.

그러니 끄지 마세요.

## 알파희에서 컴파흴러까지

| | 알파희 (rpaheui) | 컴파흴러 |
|---|---|---|
| 언어 | RPython (Python 방언) | Rust |
| 실행 방식 | 트레희싱 JIT 인터프리터 | AOT 컴파흴러 |
| 중간 표현 | 바희트코드 | CFG (제어 흐름 그래프) |
| 최적화 | RPython JIT 프레임워크에 위임 | 자체 다단계 최적화 파이프라인 |
| 출력 | 직접 실행 | 네희티브 바희너리 |
| 출시년도 | 2015 | 2026 |

## 라희선스

컴파흴러는 지나치게 빠르기 때문에, 대가 없이 사용할 수 없습니다!

컴파흴러는 **실행시간 주입 AGPL**과 **상업 라희선스**, 2개의 라희선스로 병렬 배포합니다.

### 실행시간 주입 AGPL

실행시간 주입 AGPL은 컴파흴러 그 자체뿐만 아니라, **컴파흴러로 빌드한 모든 아희 바희너리에도 AGPL이 자동으로 적용**된다는 뜻입니다. 컴파흴러 또는 컴파흴러로 빌드한 아희 코드를 판매하거나, 대중에게 공개하거나, 서비스에 이용하면 구매자 및 이용자에게 소스코드를 반드시 제공해야 합니다.
